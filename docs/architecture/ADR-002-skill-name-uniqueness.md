# ADR-002: регистронезависимая уникальность названий навыков

- Статус: принят
- Дата: 25.11.2026
- Связанная ситуация: ИС-09
- Обновляет контракт: [`data-contract.json`](data-contract.json)

## Контекст

Справочник `skills` должен содержать одно каноническое наименование навыка.
Различие только в регистре не создаёт новый навык: `Python`, `python` и
`PYTHON` обозначают одну запись.

Обычное ограничение `UNIQUE(name)` в PostgreSQL учитывает регистр и поэтому не
предотвращает такие дубли.

## Решение

Регистронезависимая уникальность `skills.name` гарантируется PostgreSQL с
помощью функционального уникального индекса:

```sql
CREATE UNIQUE INDEX uq_skills_name_lower ON skills (lower(name));
```

Проверка на уровне API в дальнейшем может выполняться для понятного сообщения
пользователю, но не является основной гарантией целостности.

## Границы решения

- Решение нормализует только регистр через `lower(name)`.
- Удаление внешних пробелов, Unicode-нормализация и исправление опечаток в это
  решение не входят.
- SQLAlchemy-модель и Alembic-миграция реализуются отдельной задачей.

## Последствия

- База данных должна отклонять вставку `python` или `PYTHON`, если уже
  существует `Python`.
- Миграция должна проверить существующие данные на конфликтующие значения до
  создания индекса.
- Имя индекса фиксируется как `uq_skills_name_lower`.
