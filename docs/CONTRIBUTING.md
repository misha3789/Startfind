# Правила работы в репозитории

## Ветки
- Каждая задача — отдельная ветка `feature/…` от актуальной `main`; исправление дефекта — `fix/…`.
- Ветка живёт коротко: одна задача, один pull request.
- Прямых коммитов в `main` нет: изменения попадают туда только через pull request.

## Коммиты
- Формат сообщения: `тип: что сделано`. Типы: `feat`, `fix`, `test`, `docs`, `chore`.
- Один коммит — одно логическое изменение. Коммитьте со своего аккаунта: e-mail в `git config user.email` должен быть привязан к вашему аккаунту GitHub, иначе вклад не засчитается.
- Историю общих веток не переписываем (`git push --force` запрещён).

## Pull request и ревью
1. Откройте pull request из ветки задачи в `main`, заполните шаблон.
2. Ревью выполняет другой участник. Автор не одобряет собственный pull request.
3. Влейте кнопкой Merge только после одобрения и зелёной проверки CI.
4. После слияния закройте связанный Issue ссылкой на pull request (`Closes #N`).

## Definition of Done
Задача выполнена, когда: код влит; тесты зелёные; документация (README, API, схемы) обновлена в том же pull request; Issue закрыт со ссылкой на pull request; результат принят тем, кто указан в плане («Как оценивается и принимается»).

## Задачи и дефекты
- Задачи и дефекты ведутся только в Issues. Каждая задача имеет владельца, этап, срок, оценку и критерий приёмки, а также ссылку на требование (FR).
- Шкала дефектов: критический, высокий, средний, низкий. Критические исправляются в день обнаружения.

## Ошибки
Все ошибки выдаются по каталогу из 27 кодов в едином формате. Новый код вносит в каталог тестировщик (`docs/testing/error_codes.md`).

## Три рубежа защиты
Каждое изменение учитывает валидацию на входе, бизнес-правила в Domain Layer и ограничения БД.

## Секреты и данные
- `BOT_TOKEN` и пароли хранятся только в переменных окружения. Файл `.env` в репозиторий не попадает, в репозитории лежит только `.env.example` с пустыми значениями.
- Персональные данные респондентов и реальных пользователей не публикуются.
- Если секрет попал в коммит, сразу перевыпустите его (токен бота — через @BotFather) и сообщите команде.

## ИИ-инструменты
Использование ИИ фиксируется в `docs/ai-usage.md`. Результат работы ИИ попадает в `main` только после запуска тестов и ревью другим участником. Ответственность за коммит несёт его автор.
