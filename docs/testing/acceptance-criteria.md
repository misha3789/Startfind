# Критерии приёмки Must-задач (этапы 1–3)

Задача принята, когда выполнены **все** критерии строки, тесты зелёные в CI, PR прошёл ревью другого участника.

| Задача | Владелец | Критерии приёмки | Проверка |
|---|---|---|---|
| Контракт данных | Архитектор | 11 таблиц, 5 статусов отклика, ADR-001/002 в `docs/architecture/` | `test_data_contract`, `test_schema_matches_er` |
| Модели и миграции | Архитектор | `alembic upgrade head` и `downgrade base` без ошибок на PostgreSQL; ограничения БД срабатывают | `test_db_constraints`, `test_application_constraints` |
| FastAPI + `/health` | Тестировщик | `GET /health` → 200 `{"status":"ok"}`; ошибки в формате `{code,message,request_id}` | `test_health`, `test_errors` |
| Auth API | Тестировщик | неверная подпись, просроченные данные, нет заголовка → 401 `AUTH_INVALID_INIT_DATA`; первый вход создаёт пользователя, второй — берёт существующего | `test_auth_roles` (ИС-01–03) |
| Роли | Тестировщик | `specialist`/`founder`, повтор идемпотентен, `admin` нельзя; чужая роль → 403 `ACCESS_ROLE_REQUIRED`; чужой ресурс → 403 `ACCESS_NOT_OWNER` | `test_auth_roles`, `test_security_access` (ИС-05, 06) |
| CI | Тестировщик | ruff + pytest + PostgreSQL на каждый PR; `main` защищён | вкладка Actions |
| Справочник навыков | Архитектор | `GET /skills?query=` от 3 символов, лимит выдачи; дубль «Python»/«python» невозможен (ADR-002) | ИС-08, ИС-09 |
| Профиль | Архитектор | `PUT /me/profile` в одной транзакции; `hours_per_week` ≥ 0; уровни `basic/confident/advanced`; нужна роль специалиста | ИС-07, 10, 29 |
| Удаление | Архитектор | `DELETE /me` каскадно удаляет данные; повтор не падает | ИС-04, 44 |
| Frontend | Менеджер | экран входа, выбор роли, `ErrorMessage` с текстами 27 кодов | ручной обход на телефоне |
| Стенд | Менеджер | HTTPS, `/health`, ежедневный `pg_dump`, секреты вне репозитория | `stand_checklist.sh`, `tests/smoke` |

# Шаблон тест-кейса

```
ID:            ТК-<этап>-<номер>          Связь: ИС-__ / FR-__
Название:      <что проверяем одной фразой>
Приоритет:     высокий | средний | низкий
Предусловия:   <данные, роли, состояние БД>
Шаги:          1. …  2. …  3. …
Ожидаемо:      <HTTP-код, код ошибки, состояние БД>
Фактически:    <заполняется при прогоне>
Статус:        ☐ пройден  ☐ не пройден  ☐ заблокирован
Дефект:        <Д-__ или —>
Автотест:      <файл::функция или «ручной»>
```
